ℹ️ About — Webhook Control Center
📋 وصف الأداة

الهدف: إدارة كل الـ Custom (API-registered) webhook subscriptions بتاعة شوبيفاي من مكان واحد — إنشاء/تعديل/حذف عن طريق webhookSubscription* mutations — بدل ما كل أداة جديدة تحتاج تسجيل الـ webhook بتاعتها يدوي عن طريق curl/GraphiQL. بالإضافة لمراقبة ذاتية البناء، لأن شوبيفاي مفيهاش أي API بيرجع delivery history أو نسبة نجاح/فشل للـ Custom subscriptions (بس متاحة جوه Dev Dashboard للـ apps المسجّلة هناك) — فالمراقبة هنا بتعتمد على جدول logs المشترك + مقارنة حية مع شوبيفاي (Reconcile).

المستخدمون المستهدفون: Ahmed (صاحب EcomModa) عند بناء أداة جديدة محتاجة webhook — بدل الرجوع لـ shopify-webhook-helper skill يدوي كل مرة.

كيف تعمل — Workflow

  1. تاب "إدارة" → "➕ إنشاء Webhook جديد" → اختر topic + اكتب uri الأداة المستقبِلة (أو دوس "🧪 استقبال هنا" لو بتجرّب) + اسم الأداة من القائمة (لازم يطابق TOOL_NAME بتاعها في D1) + الغرض.
  2. الـ FILTER اختياري: ابني الشرط بالمربعات (حقل/عملية/قيمة) أو بدّل لوضع النص الحر لو محتاج أقواس/شروط معقدة.
  3. الأداة بتنفّذ webhookSubscriptionCreate عن طريق OAuth الخاص بيها (CLIENT_ID/CLIENT_SECRET) وتسجّل نسخة محلية في جدول webhook_registry.
  4. لو استخدمت "🧪 استقبال هنا": أي event حقيقي من شوبيفاي هيوصل لنفس الأداة على /test-receive، ويظهر في تاب "🧪 تجربة الاستقبال" فيه الـ payload كامل — مفيدة قبل ما توصّل الـ topic لأداتك الحقيقية.
  5. تاب "المراقبة" → بيوري آخر نشاط لكل tool_name من جدول logs المشترك، وأي subscription اتشال من شوبيفاي بصمت.
  6. زرار "Reconcile مع شوبيفاي" (في تاب الإدارة) → مقارنة حية: أي subscription نشط محلياً بس مش موجود على شوبيفاي بيتعلّم "اتشال"، وأي subscription موجود على شوبيفاي بس مش مسجّل هنا (اتعمل من GraphiQL مثلاً) بيظهر في صندوق "غير مسجّل" مع خيار تسجيله.

🔧 تشريح الكود

FEATURE MAP

  • §AUTH — Universal D1 Auth (check_employee / register_pin / verify_employee / log_logout / get_employees)
  • §WEBHOOKS (Worker) — كل منطق الإدارة والـ reconcile والمراقبة + get_known_tool_names
  • §TEST-RECEIVE (Worker) — handleTestReceive (route /test-receive، بره الـ WORKER_SECRET gate) + get_test_received / clear_test_received
  • §SHOPIFY::metafieldEnrichment — fetchMetafieldEnrichment + METAFIELD_FETCHABLE_FIELDS allow-list — query مباشر لـ Product/ProductVariant نودز بعد كل استقبال ناجح
  • §HELPERS::safeEqual / verifyShopifyHmac — نفس نمط webhook-receivers.md، بس بـ CLIENT_SECRET بدل SHOPIFY_WEBHOOK_SECRET (لأن كل subscriptions الأداة دي API-registered)
  • §TOOL-JS (HTML) — Management tab + Monitoring tab + Test Receiver tab + Webhook form modal + Filter Builder + Metafield Fetch Fields picker
  • §LOG-ENDPOINTS — get_logs / get_logs_count / get_logs_export (نمط v2 — pagination 100/صفحة)

KEY VARIABLES

  • currentEmployee — {username, displayName} في الذاكرة فقط (لا localStorage)
  • LS_URL = 'webhook_control_center_worker_url' · LS_SECRET = 'webhook_control_center_worker_secret'
  • TOOL_NAME = 'webhook_control_center' — قيمة tool في جدول logs
  • webhook_registry — جدول D1 (مش من الـ schema الأساسي) — بيربط subscription_gid بمعلومات محلية (tool_name/purpose/notes/metafield_fetch_fields) مش موجودة في شوبيفاي أصلاً
  • test_received_webhooks — جدول D1 تاني، بيخزّن كل payload وصل على /test-receive (خام، JSON نصي) + نتيجة الـ enrichment لو حصلت
  • filterRowsState (HTML) — حالة الـ Filter Builder الحالية في الذاكرة، بتتحول لصيغة شوبيفاي عن طريق buildFilterFromRows()
  • METAFIELD_FETCHABLE_FIELDS (Worker) — allow-list مؤكدة من توثيق شوبيفاي (id/namespace/key/value/type/description/createdAt/updatedAt) — مفيش حقل بيتمرر من D1 للـ query من غير ما يتفلتر عليها الأول

NOTES

  • ⚠️ Ownership trap: list_subscriptions/reconcile بيشوفوا بس الـ subscriptions اللي اتسجلت من نفس CLIENT_ID بتاع الأداة دي. أي webhook اتسجل من GraphiQL App أو app تاني — الأداة مش هتقدر تديره، بس "Reconcile" ممكن يوريه كـ "untracked" لو لسه شغال على نفس المتجر (مش دايماً، حسب صلاحيات الـ app).
  • مفيش delivery history حقيقي من شوبيفاي — تاب "المراقبة" بيعتمد على (1) هل الـ subscription لسه موجود على شوبيفاي (Reconcile) و (2) آخر مرة الأداة المستقبِلة كتبت log — مش على نسبة نجاح فعلية للتسليم.
  • حقل "اسم الأداة" وقت الإنشاء بقى datalist من get_known_tool_names — بس لسه ممكن تكتب اسم جديد مش موجود لسه (لأداة لسه ما اتبنتش)، القائمة اقتراح مش قفل.
  • Filter Builder ببناء شروط متتالية (AND/OR) بس — من غير تجميع بالأقواس. أي حالة محتاجة أقواس (زي status:active AND (product_type:Music OR product_type:Movies)) لازم "وضع متقدم (نص حر)".
  • INCLUDE FIELDS لسه نص حر (سطر أو فاصلة لكل حقل) — القيم المتاحة بتختلف حسب الـ topic ومفيش API من شوبيفاي بيرجّعها، فمفيش dropdown ليها حالياً.
  • METAFIELDS بقى بصيغة namespace.key (نقطة) — سطر مكتوب غلط بيوقف الحفظ بتحذير واضح، بدل ما يتسجل بصمت كمصفوفة فاضية زي قبل كده.
  • ⚠️ Metafield Enrichment (query مباشر) بيشتغل بس على subscriptions الـ URI بتاعتها هو /test-receive بتاع نفس الأداة — مش أي webhook تاني. الحقول اللي بتتجاب محدّدة عن طريق checkboxes في فورم الإنشاء/التعديل (افتراضي: namespace + key + value). العملية best-effort — أي فشل فيها (مثلاً الـ metafield مش موجود على المورد ده) بيتسجل كـ {namespace, key, found:false} بدل ما يوقف حفظ الـ payload الخام.
  • ⚠️ /test-receive بيتحقق بـ HMAC مش WORKER_SECRET — أي حد يعرف الرابط ده وعنده CLIENT_SECRET الصحيح (يعني بس شوبيفاي فعلياً) يقدر يبعتله. البيانات المستلمة بتتخزن خام كما هي في D1، فلو فيها بيانات عميل حساسة، متنساش تمسحها بزرار "🗑 مسح الكل" بعد التجربة.
  • Log tab بيستخدم نمط v2 (pagination من السيرفر، 100 صف/صفحة) بدل التحميل الكامل + فلترة client-side القديمة.

الغرض
FILTER (اختياري — Shopify search syntax)
المعاينة:—
الوضع الحر بيدعم الأقواس والحالات المعقدة — الـ Builder مبني على شروط متتالية بس (AND/OR) من غير تجميع بالأقواس
METAFIELDS (اختياري)
INCLUDE FIELDS (اختياري) حقول جوّه مصفوفة (زي variants) لازم تتكتب بنقطة: variants.sku، variants.price — مش sku لوحدها، وإلا شوبيفاي بيتجاهلها بصمت. عايز الـ METAFIELDS تظهر في الـ payload؟ ضيف كلمة metafields لوحدها هنا (من غير أي إضافة بعدها).
حقول METAFIELDS في الـ Query المباشر (اختياري)
بيتفعّل بس لو الـ URI هو رابط "🧪 استقبال هنا" — بدل ما نعتمد على وصول الـ metafields جوه الـ payload (مش ثابت خصوصاً لمتافيلدز الـ variant)، الأداة بتعمل query مباشر لشوبيفاي بعد الاستقبال وتجيب بس الحقول المحدّدة هنا. الافتراضي: namespace + key + value.
